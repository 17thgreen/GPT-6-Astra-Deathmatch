# Research collaboration instructions

This repository is the canonical research home authorized by the user.

- Read README.md, docs/EXPERIMENT_REGISTRY.md and the relevant frozen specification
  before modifying an experiment. Older experiment directories are evidence
  snapshots; build new experiment versions instead of changing frozen originals.
- Commit at meaningful validated milestones during active work. First commit a
  new hypothesis/specification before observing its outcomes; then commit source,
  tests and freeze; finally commit verified results and explicit limitations.
  Do not imply a background service or scheduled commit job is running.
- The user authorized routine commits to this repository. Respect branch rules,
  preserve others' changes, never force-push, and do not overwrite an existing
  remote history. Use a research branch when work is experimental or concurrent.
- Keep negative findings, failed runs and correction provenance. Never relabel
  reused development games as holdout or report unresolved inventory as profit.
- Separate code verification, simulated execution and live validation. Verify
  financial ledgers and exact baseline controls before claiming an improvement.
- Never award the same public trade independently to concurrently simulated bots.
  Keep aggregate cash, exposure, queue ordering and exit liquidity explicit.
- Do not place live orders or change financial risk limits under a research task.
- Keep large artifacts out of routine source commits. Maintain checksum indexes
  and honest restoration instructions; do not claim indexes contain file bytes.
- Do not commit secrets, personal correspondence, unrelated files or upstream
  checkouts. Preserve source attribution; do not invent a redistribution license.
- Run focused unit tests for changed behavior. Rerun full historical experiments
  only for a declared research question or a concrete regression risk.
